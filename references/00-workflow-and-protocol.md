# 00 · 工艺与协作协议

> 这份文件回答三件事：**这东西从哪来**（上一轮对话沉淀）、**四层怎么分工**、**谁在什么时候把什么交给谁**。
> 读它一次，就知道为什么这里的每一步都「不能省」。

---

## 一、它从哪来

不是拍脑袋设计的通用排版模板，而是从一次真实的十一轮迭代里长出来的：

| 阶段 | 发生了什么 | 沉淀成了什么 |
|---|---|---|
| 1 | 拿到日本女性杂志扫描页，逐页解析版式 | 参考图 → 骨架解析法（`references/01`） |
| 2 | 用 HTML/CSS 逐页复刻 | 绝对定位 zone 原语 ＋ `layout/*.json` 归一化坐标 |
| 3 | 产品从「杂志原物」换成自家产品 | 产品层与版式层解耦（`copy/products/product.js`） |
| 4 | 原刊文字不能留 → 建文案引擎 | 槽位注入（只改直接文本节点）＋ `slots.json` |
| 5 | 日文/中文双语稿 | `?lang=jp` / `?lang=zh` 双稿机制 |
| 6 | 标签压到模特五官上 | `tools/check_faces.py` ＋ `faces.json` 禁区表 |
| 7 | 两张照片互相压住 | `tools/blockcheck.py` ＋ 透明边界框 |
| 8 | 换机器字体变了，版式全崩 | 内嵌 woff2 ＋ `tools/fontcheck.js` 字体真身自检 |
| 9 | 出现真实艺人姓名/第三方品牌/效果承诺词 | `forbidden` 四组 ＋ 双层拦截 ＋ 合规七条 |
| 10 | 版式每次微调都要手工核一遍选择器 | `build.js` 一体生成 slots/`_data.js`/HTML，改一处全同步 |
| 11 | 要能给别人复用 | **泛化成引擎**：版式×品牌×产品×文案四层，页数动态 |

**每一轮踩过的坑都固化成了脚本判据，而不是写进口诀。** 这是本 skill 的核心价值主张：
不是「教你怎么排版」，而是「给你一套**跑了会报错**的流水线」。

## 二、四层架构（记住这张图，就不会改坏）

```
                   ┌───────────────────────────────┐
  品牌管家产出 ───► │ ① 品牌层  brand/brand-pack.json│  契约见 contracts/brand-pack.md
                   └───────────────┬───────────────┘
                                   │ build.js 读 → 生成 brand/_skin.css（配色+字体覆写）
                   ┌───────────────▼───────────────┐
  你看参考图解析 ──► │ ② 版式层  layout/*.json        │  页数 = 文件个数 = 参考图张数
                   └───────────────┬───────────────┘
                                   │ build.js 读 → 渲染绝对定位 zone → pageNN.html
                   ┌───────────────▼───────────────┐
  供货方信息＋肉眼 ─►│ ③ 产品层 products/product.js   │  只写可见事实，每条带来源
                   └───────────────┬───────────────┘
                                   │ 提供 ${price} ${size} 等变量
                   ┌───────────────▼───────────────┐
  品牌语气重写 ────► │ ④ 文案层  copy/issue.js        │  每槽位 { jp, zh } 成对
                   └───────────────┬───────────────┘
                                   │
                   build.js ─► page01.html … pageNN.html + index.html + copy/_data.js + copy/slots.json
                                   │
                   shoot.js ─► _shots/page01.png … pageNN.png   （逐页用自己的参考图尺寸）
```

### 只有两个接口

1. **品牌包契约**（`contracts/brand-pack.md`）——品牌层 ↔ 引擎。
2. **layout JSON 骨架**（`references/01`）——参考图 ↔ 引擎。

其余全部解耦。所以：
- 换品牌 → 只换 `brand-pack.json`；
- 换产品 → 只换 `products/product.js` ＋ `issue.js` ＋ 替换 `images/` 同名素材；
- 换参考图 → 只换 `layout/`（页数自动跟着变）。

**「换产品不碰 HTML」不是口号**：页面 `<script src>` 是固定文件名，
`copy/_data.js` 由 build 重新生成。你不需要、也不应该在生成的 `pageNN.html` 里改任何东西。

## 三、协作协议

### 3.1 角色

| 角色 | 是谁 | 交什么 | 不做什么 |
|---|---|---|---|
| **品牌侧** | 品牌管家 skill（如 `yurutae-brand`；品牌不存在时先用 `brand-creation` 建） | `brand-pack.json`（按契约） | 不碰版式、不写整期文案 |
| **执行侧** | 本 skill | 杂志图 PNG ＋ HTML 源 ＋ 总览 ＋ 台账 | 不改品牌定案（名字/理念/Slogan/署名/禁用清单） |
| **你** | 决策者 | 参考图、产品信息、价格、素材、拍法 | —— |

### 3.2 交接格式（品牌侧 → 执行侧）

品牌侧不需要懂 JSON 之外的任何东西。把这份要求直接给它：

> 请按 `brand-magazine/contracts/brand-pack.md` 产出一个 `brand-pack.json`。
> 至少给 `brandId` / `defaultLang` / `name` / `forbidden`；
> 有署名规范给 `signature`，有广告语给 `slogan`（含配平句），有配色与字体给 `palette` / `fonts`。

**`compliance.escalate` 必须如实带上**——它是对「本引擎不保证什么」的声明。

### 3.3 品牌层的真源

- 品牌定案的**真源永远是品牌侧 skill**。本引擎里的 `brand-pack.json` 是**带上的一份快照**。
- 两边不一致时 → 以品牌侧为准，并把差异回报给它。
- **本 skill 不改品牌定案。** 要改名字/理念/Slogan/署名/禁用清单，去品牌侧改，再重跑 `node build.js`。

### 3.4 协作红线（来自上一轮对话的七条合规要求，长期有效）

1. **人物**：页面出现的一切姓名/署名只能来自品牌侧。
   即「下着の作家／内衣作家」与品牌名。**禁止真实艺人姓名、履历、肖像指涉。**
2. **履历栏**：一律写产品事实（尺寸/结构/面料/颜色），不写人物经历。
3. **AI 标识**：按项目决定——默认**不写**「AI 生成」字样；但素材台账要如实备案生成过程（**事实记录 ≠ 对外标识**）。
4. **品牌**：只出现品牌侧提供的品牌。第三方真实品牌全部清除；
   `forbidden.brands` 里的旧品牌检测词**保留**，供编译期兜底。
5. **价格**：用户未提供 → 一律默认 `¥1,950`（或品牌包 `price.defaultPrice`）。
6. **素材台账**：每新增/替换素材必须登记进 `ASSETS.md`；参考图仅内部叠图比对，**不随成品分发**。
7. **改版式流程**：改 HTML 元素 → 同步 layout JSON 的 zone id 与 `:nth-of-type` 位次 →
   重跑 `node build.js`（自动重生成 `slots.json`）→ `node tools/copycheck.js` 全绿 → 才重出图。

### 3.5 我在执行时必须做的三件事

1. **现场重跑，不吃旧产出。** 不许引用上一轮的结果说「已经通过了」。
2. **参考图识别不了就停。** 图看不清/读不出骨架 → 立即停下告诉用户，不要猜着往下做。
3. **任何本地操作先获授权。** 用户说停就停。

### 第 2 / 7 条展开：用生图通道补「拍摄图」时的七个操作要点

参考刊的人物写真多半拿不到授权，用 ImageGen 补「封面级拍摄图」是常规做法。六个要点（都是踩过的）：

1. **必须喂实物参考图（image-to-image），不要纯文字生成。**
   把抹过水印的实物照作为 `image1`，提示词里点明「wears the ... shown in the reference image」。
   目的不是好看，是让服装与实物一致 —— 否则生成的图与真货不符，
   在下着／服飾品类直接踩景表法的「優良誤認」。生成图**只作版面氛围**，
   **不得当作产品形态／合身度／颜色的依据**。

2. **提示词里显式交代「给刊头留白」。**
   参考刊的封面骨架常在四角压大字与白卡，若生成的写真把主体塞满，
   刊头就只能压在脸上。写法：`Keep clean empty background in the upper-left and
   upper-right corners for cover typography.`

3. **★提示词里还要交代三件事，否则版面一定对不上**（第 ①②⑦ 点就是这么漏的）：

   | 要交代的 | 怎么写 | 为什么 |
   |---|---|---|
   | **背景基色** | `background: pale cool blue (#DEE4F1), flat seamless studio backdrop` | 生成图自带的暖灰底会在版面上与参考刊的冷蓝底打架，而「米灰 vs 天蓝」这种差别**中位亮度只差 3**，判据看不出来，只有四角基色的**冷暖轴 R−B** 能看出来 |
   | **主体轴心 x** | `subject centred at about 30% from the left edge` | 参考刊的主体轴心是几，决定了左侧留白多不多、右上白卡放不放得下 |
   | **主体触边** | `the drape/shoulder must run off the right edge of the frame` | 参考刊主体顶到哪几条边，画面才「满」。不触边 → 右侧一片平底 → 成品显得空 |

4. **生图工具会在右下角打自己的水印**（如「AI生成／WORKBUDDY」，位置约 y ≳ 0.92）。
   **优先用「裁窗」去掉，不要用抹除工具** —— 裁掉比抹更干净，也不改动像素。
   做法：本工具出的是 2:3，而版面画框多半不是 2:3，本来就要自己裁。
   把裁窗上下界定成「保住主体发顶」到「0.87 左右」即可一并避开。
   裁完再 resize 到版面画布，别把裁切交给 CSS 的 `object-fit: cover`（裁在哪不由你决定）。
   生成图要在 `ASSETS.md` 单列登记（角色 `gen`）并写明「仅内部留档」。

5. **同一提示词出 2 个候选，只把选中的那一版登记进台账。**
   落选候选留在工作目录（如 `_work/gen/`）备查，**不要塞进 `images/`** ——
   那个目录的文件名要能跟 `layout` 的 `src` 一一对上。

6. **★提示词只是「要求」，出图之后必须做一次像素级复核与重排 —— 别只信提示词。**
   提示词是概率性的；**真正保证「背景色对、主体轴心对、主体触边对」的是这一步**：

   ```bash
   # ① 从参考图量出目标背景基色（四角取中位，丢掉被主体/白卡污染的角）
   python tools/refdims.py --bg
   # ② 按目标色重铺背景 + 平移主体；顺带吐一张对齐的遮挡掩膜
   python tools/herorecut.py images/raw-hero.png images/p01-hero2.jpg \
          --dx -0.26 --bg "#E4EBF6" --size 1280x1617 --emit-mask images/p01-submask.png --check
   # ③ 复核读数：主体轴心 x 与四边接触率（掩膜的「洞」就是主体轮廓）
   python tools/refdims.py page01 | grep 模特
   ```

   `herorecut.py` 是**非生成式**的纯像素运算（掩膜 → 平移 → 整片重铺背景基色 → alpha 合成），
   所以服装像素一个都没被改动，合规边界不受影响。
   **第 ① ② ⑦ 点（背景色 / 刊头被遮 / 主体偏左）最后是在这一步解决的，不是靠改提示词。**

7. **★「主体触边」要对表，而且对表时别把判据当目标去迎合。**

   触边率（该边 3% 宽带内主体像素占比）是第 7 点唯一能量化的东西，但**参考侧不能自动量** ——
   参考封面是合成页，`rembg` 会把右上白卡并进「主体」（实测上半幅跨度 0.77、列投影无缺口，
   头心算出 0.581 而真值约 0.35）。所以规程是三步：

   ```bash
   # a) 出 20×20 网格并排读图，人工读数写进 assets/ref/_readings.json（键名有 schema 校验）
   python tools/refdims.py page01 --grid
   # b) 判据自动对表：头心 x 差 > 0.06 或触边率差 > 15pp → 硬缺失，且归属为「生图层」
   python tools/refdims.py page01 --check
   # c) 反解重裁参数；工具在「头部完整 + 头心 x 锁死」的硬约束内穷举
   python tools/herorecut.py images/p01-hero2.jpg --check --head-x 0.35 \
          --fit-touch "T=33,B=100,R=40"
   ```

   > ⚠️ **两个已经踩过的大坑：**
   >
   > **(1) 接触率单独做目标函数会被作弊。** 只优化 T/B/R 会解出 `scale=1.655`，
   > 四条边全达标 —— 但画面上**头已经没了**（主体顶边跑到 −0.615）。
   > 所以硬约束（头部完整性、头心 x）必须与目标**分离**，越约束的解直接丢弃。
   > **接触率高 ≠ 构图对。**
   >
   > **(2) 搜不出解时，正确的结论是「回生图层」，不是继续调参数。**
   > 工具的残余报告若在穷举后仍不达标，它会明说：
   > 「这张照片里没有能填满 R 的内容（参考刊靠裙摆铺满，本片是棚拍平底裁切）」。
   > **不许用拉长卡片、加装饰、放大字号去填那一格** —— 那是掩盖，
   > 而且一换产品素材就全部失效。

### 第 12 条展开：分层优先

「尽量保留原刊的文字样式，如果没有就找最相似的」——当它与品牌视觉约束冲突时：

| 跟原刊（视觉气质层） | 跟品牌（约束层） |
|---|---|
| 字体气质（明朝 / 黑体 / 手写 / 拉丁衬线） | 颜色（走品牌 `palette`） |
| 字号层级（谁是主角、谁是注脚） | 字重上限（`visual.maxWeight`） |
| 排向（横排 / 竖排） | 禁用装饰（`visual.banned`） |
| 字距、行距 | 留白下限（`visual.minWhitespace`） |
| 分区比例与元素相对位置 | 禁用词（`forbidden`） |

落地方式：版式 JSON 里 `style.font` **只写角色名**（`serif`/`sans`/`script`/`latin`），
字号写具体 px；颜色写**令牌名**。于是「气质跟原刊、颜色跟品牌」是**同一个字段的两种取值方式**，
不需要二选一，也不需要事后打补丁。
