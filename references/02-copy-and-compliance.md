# 02 · 文案与合规

> 「全部重写为品牌语气」这条决策的执行手册。分三块：**怎么写**（§一–§三）、**不许写什么**（§四）、
> **怎么被机器拦住**（§五）。

---

## 一、占位符与槽位口径

### 1.1 两种占位符，别混

| 写法 | 名字 | 谁给值 | 出现的层 |
|---|---|---|---|
| `${1}` `${2}` | **槽位** | `copy/issue.js` 的 `jp` / `zh` 数组，按下标对应 | 版式 `tpl` |
| `${brand}` `${brandzh}` `${brandro}` `${price}` `${size}` … | **变量** | 品牌包 / `product.js` 的 `vars` | 版式 `tpl` **和** 文案文本里都能用 |

**数量必须相等**：`tpl` 里有几个 `${n}`，`issue.js` 里那一项就得给几个值。
少给一个 → `build.js` 报错退出；多给一个 → 同样报错。**不猜、不自动补空。**

### 1.2 槽位键 = CSS 选择器

`copy/issue.js` 的键就是**选择器字符串**，固定形态 `#<zone-id> > .t`：

```js
window.__ISSUE = {
  page01: {
    '#s1-h > .t': { jp: ['素材を', '手で整える'], zh: ['用手', '整理素材'] },
    '#pageno > .t': { jp: '51', zh: '51' }     // 单值 = 字符串
  }
};
```

- **单值写字符串，多值写数组。** 数组顺序 = 元素里**直接文本节点的顺序**。
- 元素里有 `<b>A</b>` 或 `<span class="box">` → **那些不是槽位**，
  它们对应的文本节点在 `<b>`/`<span>` 里面，槽位只管**外层的裸文本**。

### 1.3 什么算「一个直接文本节点」

```html
<div class="z z--text" id="s1-h"><div class="t"><b>01</b> ${1}<br>${2}</div></div>
```
- `${1}`、`${2}` 是 2 个槽位；
- `<b>01</b>` 里的 `01` **不是**槽位（它在子元素里）。

**注意空白**：只有空白的文本节点会被引擎忽略。所以
`"${1}\n    <br>${2}"` 仍是 2 个槽位。

## 二、文笔规范（品牌语气转换 8 条）

品牌定案由品牌包 `tone` 段携带。以下八条是**通用转换手法**，用来把「原刊的语气」翻成「品牌语气」。

### 2.1 主语换成物，不评价人

| ✘ 原刊/AI 味 | ✔ 品牌味 |
|---|---|
| あなたの悩みを解決 | 布が、縫い目が、そう決まっている |
| 誰でも似合う | サイズは 3 段階。選ぶのは自分 |
| スタイルアップ | 構造を、そのまま |

**理由**：品牌声音是「物自己说出来」，一旦主语变成人就开始讨好，就是品牌明确不要的姿态。

### 2.2 不写体感，改写成构造

| ✘ | ✔ |
|---|---|
| ふわふわで気持ちいい | 起毛なしの平織。肌に当たる面は縫い代を外へ |
| 締め付けゼロ | ゴム幅 12mm。伸び率は実測 1.8 倍 |
| 通気性バツグン | 組成 95% ポリエステル / 5% ポリウレタン |

**铁律**：**未实测的一律改写为构造描述**，或标注来源（`試着記録より` / `supplier sheet`）。

### 2.3 不出现工艺声称

不要「私たちはこう織っています」「〜製法を採用」。工艺信息不是不能有，
而是**必须走引用体或事实体**：「平織（供給元資料による）」。

### 2.4 年份・传承・产地走引用体，不走声称体

| ✘ 声称体 | ✔ 引用体 |
|---|---|
| 創業 100 年の技術 | 供給元資料に「創立 100 年」と記載 |
| 日本製のこだわり | 産地は未確認（組成のみ確認済み） |

### 2.5 话少、手准 —— 宁缺勿满

品牌声音是「停止试图讨好之后的样子」。**一句话能说完就别写两句。**
每页正文总量：中文/日文合计控制在参考图的 **80–110%** 之间（见 §三）。

### 2.6 竖排句要能独立成段

竖排句（`note-v`）通常是全页唯一一句「呼吸」。写它的时候：
- 一句到底，不在中间断气；
- 不加标点收尾（`。` 可留可去，按品牌定案）；
- 不出现数字（数字在竖排里要转全角，很丑）。

### 2.7 Step / 编号小标的写法

`Step` 词用 `script` 角色保留拉丁（跟原刊文字样式）；编号用 `latin` 96px。
**编号本身不进文案**（`tpl: "1"` 写死），只有小标与说明进槽位。

### 2.8 中文对照稿不是翻译

`zh` 稿是**同义异码**，不是逐字翻译：字数要更短（中文同义通常比日文短 10–20%），
语气要同样克制。中文稿**不对外发布**，只给你审读用。

## 三、长度控制（防溢出）

`copycheck` 会实测渲染后几何，但**写的时候就该按预算写**：

```
node build.js --brief      # → copy/_brief.md
```

`_brief.md` 给每个槽位三项数据：

| 列 | 含义 |
|---|---|
| `部件数` | 这个槽位有几个 `${n}`（= 要几个值） |
| `每行字数` | `(框宽 - padding) / (字号 × (1 + 字距))` —— 一行能放几个字 |
| `字号` | 该槽位的 px |

**经验值**：

| 语言 | 相对日文的长度 |
|---|---|
| 日文（jp） | 基准 1.0 |
| 中文（zh） | 同义通常 **0.8–0.9**，但若日文用了汉字词，中文可能更短 |
| 英文（拉丁） | 视词长，`latin` 角色多用短词/字母 |

**溢出高危区**（历史上都出过事）：

| 位置 | 原因 | 对策 |
|---|---|---|
| 三段式刊头 `mast-c` | 多两个字就顶穿 | 文案压到最短，或 box 加高 |
| Step 说明 `sN-p` | 中文比日文长，且框只有 0.068 高 | 控制在 2 行内 |
| NEWS 双栏的短栏 | 长栏字数多，两栏高度不一致时视觉歪 | 两栏字数**主动配平** |
| 引线标注 `lab-*` | 框小且坐标密 | 一行 6–8 字以内 |

## 四、不许写什么（四法规红线）

品牌包 `compliance.regimes` 默认四项。以下按「会被哪个法拦」分类。

### 4.1 景品表示法（優良誤認・有利誤認）

| 类别 | 例（**一个都不许写**） |
|---|---|
| 空泛最高级 | 究極 / 最高 / 奇跡 / 贅沢 / 圧倒的 / 極上 |
| 效果承诺 | 寄せ上げ / 集中 / 補正 / 育乳 / 肩こり軽減 |
| 体感保证 | ふわふわ / 締め付けゼロ / 通気性バツグン |
| **未声明的标签** | 若产品信息里**没有**折扣，就**不许**出现折扣 icon；没写包邮就不许出现包邮标 |

> **「数据驱动」是硬规则**：Badge 只能来自产品信息里明确出现的事实。
> 未提及 → 一律不加。这条比任何文案技巧都优先。

### 4.2 家庭用品品質表示法

- 組成（纤维混用率）**必须**与供货方资料一致，不许四舍五入、不许美化。
- 洗濯表示（JIS 记号）、表示者名：**未确认就不写**，或标 `未確認`。

### 4.3 薬機法

- 内衣类不得出现医疗/保健功效表述（血行促進、肩こり改善、姿勢矯正…）。
- 「ノンワイヤー」「無鋼圈」在**未确认真无钢圈时**不得使用（属性能声称）。

### 4.4 特定商取引法

- 署名不附地名（`signature.noPlaceName`）。
- 法定表示栏写**责任主体（表示者名）**，不写人格化署名。
- 促销信息一律**图标化**（`visual.badgesIconOnly`），不写进正文语句。

### 4.5 地缘来源 ≠ 材料来源

**这两个不许混用**：
- `日本製`（地缘）≠ `日本産の綿`（材料）；
- `京都で縫製` ≠ `京都の布`。

未确认前**一个都不写**。这条是上次迭代里明确列出的红线。

### 4.6 Slogan 配平（品牌专属规则）

品牌包 `slogan.mustPair` 声明了「slogan 出现时必须紧跟的句子」。
`slogan.native` 一旦出现在页面上，其后 60 字内必须以 `mustPair` 任一句开头，否则 `copycheck` FAIL。

**为什么**：品牌 slogan 是软句，单独出现会被读成讨好姿态；配一句把决定权交回读者的句子才成对。

## 五、机器怎么拦（三层）

```
写文案
  │
  ├─► node build.js            ← 编译期
  │     ① 槽位值个数 ≠ tpl 的 ${n} 个数 → 退出码 1
  │     ② 正表记稿命中 forbidden 四组 → 退出码 1
  │
  ├─► node tools/copycheck.js  ← 渲染后（必须全绿才出图）
  │     A 接口层  选择器命中唯一 1 个元素；无两个选择器撞同一元素
  │     B 注入层  值个数 == 直接文本节点个数；jp / zh 都齐
  │     C 覆盖层  slots.json 里每个槽位都被本期文案写到
  │     D 合规层  渲染后正文无 forbidden 词；Slogan 按 mustPair 配平
  │     E 版面层  ① 静态：文字框互压（layout JSON 直接算）
  │               ② 动态：渲染后无溢出、无出画布
  │
  └─► 目检        视觉上过一遍品牌约束
```

**为什么 D 组要在渲染后扫，而不是只扫源文件**：JS 注入发生在浏览器里，
`${price}` 这类变量替换的结果只有渲染后才存在；而且 `<title>` / `alt` / 注释
在源文件里容易漏检。**两份清单都要有，只留一份会漏。**

## 六、写文案的推荐顺序

1. `node build.js --brief` 拿字数预算
2. 通读品牌包 `tone` 段 + `forbidden` 段（**照抄，不要凭记忆**）
3. 先写 `jp`（正表记）——它是成品语言，要写到位
4. 再写 `zh`（对照）——同义异码，更短、同样克制
5. `node build.js` → `node tools/copycheck.js`
6. 报错就读错误信息里的**实测差值与字数**，回去改文案或改 layout box
7. 全绿后 `node tools/shoot.js` 出图，目检

## 七、示例：一页文案怎么从「原刊味」变成「品牌味」

**原刊（参考图上的文字，一律不许留）**：
> あなたの体型を美しく見せる魔法の下着。ついに新色登場！
> ふんわり包み込む、極上の着け心地。

**改写步骤**：

| 步骤 | 处理 |
|---|---|
| ① 拆事实 | 新色 → 颜色数；包み込む → 覆盖结构；着け心地 → 无实测 → 改写构造 |
| ② 换主语 | 主语从「あなた」换成「布 / 縫い目 / 構造」 |
| ③ 去声称 | 美しく見せる（效果）→ 删；魔法（最高级）→ 删 |
| ④ 去体感 | ふんわり包み込む → 「肌に当たる面は縫い代を外へ」 |
| ⑤ 补事实 | 颜色数、サイズ段階、組成 —— 只写产品信息里有的 |

**成稿（jp）**：
> 新色 3 色。サイズは M / L の 2 段階。
> 肌に当たる面は、縫い代を外側へ。組成は 95% ポリエステル / 5% ポリウレタン。

**成稿（zh）**：
> 新色 3 色。尺寸 M / L 两段。
> 贴肤面缝份向外。组成 95% 聚酯 / 5% 聚氨酯。

## 八、自检清单

- [ ] `node build.js` 无报错（槽位个数、禁用词）
- [ ] `node tools/copycheck.js` **退出码 0**（五组全过）
- [ ] 页面里没有真实人名、没有未确认第三方品牌、没有效果承诺词
- [ ] 价格 = 实际价，或品牌包 `price.defaultPrice`（默认 `¥1,950`）
- [ ] 促销信息只有图标，没有写进正文语句
- [ ] Slogan 出现时已配平
- [ ] 每页正文总量在参考图的 80–110%
- [ ] 中文对照稿不是逐字翻译
