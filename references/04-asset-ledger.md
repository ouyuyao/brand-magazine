# 04 · 素材台账（ASSETS.md 模板）

> **用法**：把下面的模板复制成**项目根的 `ASSETS.md`**，逐次交付时填写。
> 每新增/替换一个素材（图片、字体、参考图、生成图），**必须登记一行**。
>
> 为什么必须有它：杂志图的合规风险不在代码里，在**素材的来源**上。
> 参考图是从别处采集的、生成图是 AI 出的、字体是第三方授权——这些如果没记录，
> 三个月后你无法回答「这张图能不能商用」「这个字形哪里来的」。

---

## 台账字段说明

| 字段 | 含义 |
|---|---|
| **文件** | 相对项目根的路径 |
| **角色** | 用途：`hero`（主视觉出血图）/ `plate`（实底照）/ `step`（步骤小图）/ `detail`（细节特写）/ `cutout`（抠底单品）/ `ref`（参考图）/ `font`（字体）/ `gen`（AI 生成） |
| **来源** | `自拍` / `供货方` / `采集（网址）` / `AI 生成（工具+prompt 摘要）` / `第三方授权（授权书）` |
| **尺寸** | 像素 w×h |
| **hash** | `sha256` 前 12 位（用于确认「这一版到底是哪一版」） |
| **授权/合规** | 可否商用、有无署名要求、有无肖像权/著作权风险 |
| **分发范围** | `成品内` / `仅内部比对（不随成品分发）` / `仅工具用` |
| **登记日期** | YYYY-MM-DD |

## 生成 hash 的命令

```bash
# 单个文件
sha256sum images/p01-hero.jpg | cut -c1-12

# 整个素材目录（用于确认「这一版素材」）
sha256sum images/* | sort | sha256sum | cut -c1-12

# Windows PowerShell
Get-FileHash images\p01-hero.jpg -Algorithm SHA256 | Select-Object -ExpandProperty Hash
```

## 四条硬规则

1. **参考图不随成品分发。** 它只用于内部叠图比对（`pageNN.html` 按 `O` 键）。
   交付时 `assets/ref/` 可以整个不带。
2. **AI 生成必须备案。** 备案 ≠ 对外标识。两者是两件事，都要做对：
   台账里如实写，页面上按品牌决定（本项目：不写）。
3. **未确认的就不写。** 产地、纤维混用率、洗濯记号、表示者名——
   没有供货方资料或行政書士确认的，一个字都不写进页面，台账里标 `未確認`。
4. **⚠️ 供货方素材上的第三方标识，必须抹除并留档。**
   电商供货图几乎都带水印／供货方品牌字（常见形态：产品右下方背景上的白色半透明艺术字）。
   **它随派生裁切一路带进成品，而且肉眼在整页图上很难注意到** ——
   既构成品牌混淆，也在景普表示法与商标使用上留下风险。
   交稿前必做：
   ① 「右下角对照拼图」逐张目检（`python tools/wmsheet.py --dir images` —— 把每张素材右下角裁出来排成一张）；
   ② 抹除用**中值滤波差异法**（`python tools/unwatermark.py <file> --win x0,y0,x1,y1 [--dry]`）——
      中值滤波吃掉细笔画、保留大结构边缘，仅当原像素比中值亮 2.5 灰阶以上才替换。
      **绝不要用「涂白」或「整块模糊」，那会破坏产品轮廓**；
   ③ 改动的图**要留处理前的备份**（`unwatermark.py` 自动备份到同目录 `_before_unwatermark/`），
   台账里单独开一节写清「哪几处、什么位置、怎么处置的、结果如何」。
   自动检测器（按亮度找亮簇）**只作辅助**：大面积白色产品会把它喂成一片假阳性，
   最终判据永远是**人眼看对照拼图**。
