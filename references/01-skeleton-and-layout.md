# 01 · 骨架解析与 layout JSON 规格

> 这是「**第 i 页沿用第 i 张参考图的结构**」这条决策的落地说明。
> 你要做的事只有一件：**看参考图，写 layout JSON**。写完 `node build.js` 就出页面。

---

## 一、什么叫「骨架级复刻」

不是像素级描摹（那要逐像素对齐，换素材就全废），也不是意译（那叫原创不叫复刻）。
是**保留结构，让尺寸随素材自适应**：

| 复刻 ✔ | 不复刻 ✘ |
|---|---|
| 分区比例（谁占上半页、谁占三分之一） | 字号的具体数值（除非它本身就是设计主体） |
| 层级（谁压谁、谁是主角、谁是注脚） | 图片的具体像素位置 |
| 留白节奏（哪里密、哪里松） | 原刊的字体文件（用角色替代；识别流程见 `references/05-font-identification.md`，替代台账见 `contracts/brand-pack.md §3.7`） |
| 元素相对位置（页码在角、署名贴边、编号压在图上） | 原刊的文字内容（**一律重写**） |
| **文字样式气质**（明朝/黑体/手写/拉丁；横排/竖排；字距行距） | 原刊的颜色（走品牌 `palette`） |

**判断标准（两级）**：

1. **硬判据** —— `python tools/refcheck.py` **退出码 0**：页数 = 参考图张数、
   每页 `canvas` = 该页参考图的真实像素尺寸。这两条不符就是「有页没解析」或
   「叠图从根上失真」，**不进下一步**。
2. **告警判据** —— 页面按 `O` 键在三态间切换（成品 → 叠参考图 → 叠差异图），
   分区边界应基本重合、差异图上没有成片高热区；再跑 `python tools/reffit.py`
   看骨架吻合分（≥ 0.80 正常）。分数低**不阻断**，但连续偏低说明解析没做扎实。

文字块的**气质**应一眼可辨为同族——但材质、颜色、内容都是你的。

## 二、解析流程（一张参考图 → 一个 JSON）

> **先跑工具，再动笔。** 下面第 1–3 步都有工具替你量，别用眼睛估——
> 估出来的 box 是 reffit 分数上不去的头号原因（出厂示例就是这么来的，它的
> page05 吻合分只有 0.49，缺的正是 22.6% / 62.0% 两条带缝）。

### 第 0 步 · 让工具先读参考图

```bash
python tools/refscan.py            # 读 assets/ref/ 下所有参考图
```

它做的是**行 / 列边缘投影**：把参考图灰度化，逐行求「相邻像素差」的横向均值，
再在曲线上找「静默谷」——那就是内容带之间的缝。输出：

- `assets/ref/_scan/<name>.json`：候选切分点（`bandCuts`，含 `conf` 置信度）、
  每条带内的分栏位置（`columns`）、图像真实尺寸（`size`）
- `assets/ref/_scan/<name>.bands.png`：候选线**叠在原图上**，一眼看对不对
- `assets/ref/_scan/<name>.profile.png`：投影曲线本身

```bash
python tools/refgrid.py p01.jpg            # 百分比坐标网 + 叠图 + 差异热图
python tools/refgrid.py p01.jpg --shot page01   # 与成品页对拍，出 _diff.png
```

**这是「起点」不是「答案」**：工具给候选，人来判断哪条缝是真的（照片内部的
软过渡也会被算成谷，靠 `conf` 与 `.bands.png` 目检排除）。

### 第 1 步 · 量画布

`refscan` 的 `size` 字段就是参考图的**真实像素尺寸**，直接抄进 `canvas`。
**逐页用自己的尺寸**（各页可不同）。

```json
"canvas": { "w": 1366, "h": 1748 }
```

⚠️ `canvas` **必须等于该页参考图的真实尺寸** —— `tools/refcheck.py` 与
`build.js` 都会硬断言（退出码 1）。抄错尺寸 = 叠图从根上就缩放错位，
后面所有目检都失去意义。

### 第 2 步 · 切横带（3–5 条）

`refscan` 已经给出候选切分点（`bandCuts`），**以它为准**，只在明显误判时才手改：

```
p05.jpg                 1366x1748  候选切分点 3 条
    y=22.6%  conf=0.78     ← 刊头带 / NEWS01 带
    y=62.0%  conf=0.78     ← NEWS01 带 / NEWS02 带
    y=95.8%  conf=0.80     ← NEWS02 带 / 页脚带
```

对应 `box` 的 `y` 就写这些数字（`0.226` / `0.620` / `0.958`）。

**这一步决定版式的骨架，做对了后面都顺。** 校正用
`python tools/refgrid.py <ref>` 叠百分比网，或 `--zoom 4 --crop x,y,w,h` 局部放大看交界。

### 第 3 步 · 每带里切列

`refscan` 的 `columns` 同样是候选值，按带分别给出：

```
    band0 0.0%-22.6%  分栏 4.6% 11.8% 44.3% 90.5% 97.3%
    band1 22.6%-62.0%  分栏 96.2%
```

即：刊头带在 4.6% / 11.8% / 44.3% / 90.5% 处有分栏（左侧撕纸标 + 右侧三段刊头），
NEWS01 带在 96.2% 处有一条右边线。**列的位置不要平均分配**，照读数写。

### 第 4 步 · 逐块定 kind 与内容

| 看到什么 | kind |
|---|---|
| 一段文字（标题/说明/注记） | `text` |
| 矩形照片，满框裁切 | `image`（`treat: "frame"`） |
| 出血大图（贴边、可能被压） | `image`（`treat: "bleed"`） |
| 抠了底的物件（无框，压在其他元素上） | `cutout` |
| 圆形/异形裁切的照片 | `mask`（`mask: "circle"`） |
| 细线（分隔、装饰） | `rule` |
| 实色横带/竖带 | `band` |
| 半透明底色块 | `panel` |
| 小圆/小方标签 | `badge` |
| 撕纸边标签 | `torn` |
| 圆形气泡文字 | `bubble` |
| 品牌 logo | `logo` |
| 引线标注（细线 + 小字） | `label` |

### 第 5 步 · 记文字样式（**这一步别偷懒**，它就是「保留原刊文字样式」）

对每个文字块记**五件事**——前四件是「字长什么样」，第五件是「字怎么排」。
少了第五件，就会出现「字体字号颜色全对、气质全错」：
参考刊那个词是**沿弧线斜排**的，你平摆一句，谁看都不像。

1. **气质** → `style.font` 写**角色名**：`serif` / `sans` / `script` / `script-fat` / `latin` / `latin-ital`
2. **层级** → `style.size` 写 px（照原刊的视觉大小换算到你的画布）
3. **排向** → 竖排写 `"writing": "v"`（需要正立再叠 `"upright": true`）
4. **节奏** → `style.tracking`（字距 em）、`style.leading`（行高倍数）
5. **★排列方式** → 这一项**必须显式落字段**，不能靠「平摆看起来也还行」含糊过去：

| 参考刊怎么排 | 写什么 | 读出来是什么 |
|---|---|---|
| 平摆一行 | 什么都不写 | `横排` |
| 竖着一列 | `"writing": "v"` | `竖排` |
| 整块倾斜 | `"rotate": -24`（度，逆时针为正） | `斜排` + 角度 |
| **沿弧线排** | `"arc": { "cx":0.5, "cy":4.4, "r":0.88, "mid":-90 }` | `弧排` + `r`/`mid` |

`arc` 的几何约定（写死，不要反）：
- `cx / cy` 是**相对本框**的归一化圆心；`cy < 0` → 圆心在框上方 → 弧向下凸（下垂弧）；
  `cy > 1` → 圆心在框下方 → 弧向上凸（彩虹弧）。**所以「上拱弧」要写 `cy > 1`。**
- `r` 是半径，**相对本框宽度**。`r` 越小弧越弯；`r ≥ 3` 基本就是直线。
- `mid` 是弧中点角度：`0`=右、`90`=下、`-90`=上、`180`=左。
- 省略 `span` 时按文字实际长度**自动撑弧**（`<textPath>` 超出路径长度的部分不绘制，
  不自动撑弧会静默吃掉半句）。方向自动判定为「左→右、正立」，不必也不该由人指定。
- `rotate` 与 `arc` **可以叠用**：弧排给弯，`rotate` 给整体的斜。

> **量参考图的弧度怎么估**：用 `refgrid.py --zoom --crop` 放大弧排字，
> 记三个点（弧的起点、中点、终点）的坐标，套「三点定圆」估 `r` 与 `mid`。
> 估不准就先写 `r` 的粗略档位（1.2 很弯 / 1.8 中弯 / 3.0 近直），出图后对着参考图调一到两轮。

**货币写法（日本站硬规则）**：价格一律 `1,988円`，**不写 `¥1,988`、不写 `￥`、不写 `元`**。
`¥` 是人民币/日元的混用符号，日语读者读的是「円」；它同时也是排版问题
（符号基线与日文不齐）。`refdims.py ②` 会扫 **layout 的 tpl + `copy/` 全部 `.js`**
（带注释剥离 —— 规范文档里会写「不写 ¥1,988」，那是反面示例，不是使用），
命中即硬失败。**注意：价格字符串常常住在 `copy/products/*.js` 的 `vars` 里，
layout 里只有 `${price}`；只扫 layout 会永远读到「0 个円」然后给出假绿。**

**颜色不记。** 颜色写**令牌名**（`ink` / `ink-2` / `accent`…）交给品牌包；
只有「必须压在照片上的白字」这类才写字面色值 `"#ffffff"`。
但**压照片的字要按对比度反算令牌取值**，不要凭眼睛：`contrastcheck.py` 实测出底的中位灰度后，
正文要过 4.5、大字要过 3.0，令牌的加深档就由这个反算出来（见 §九）。

### 第 6 步 · 写 tpl（文案占位）

- `tpl` 里 `${1}` `${2}`… 是**文案槽位**，按出现顺序编号。
- **元素子节点照写标签**：`"${1}<br>${2}"`、`"<b>A</b> ${1}"`。
- 没有槽位的纯装饰文字直接写死（`"tpl": "Step"`），就不用写文案。

### 第 7 步 · 编译 + 叠图 + 打分

```
node build.js
python tools/refcheck.py       # 先过硬断言（页数 / canvas 尺寸）
```

浏览器打开 `pageNN.html` → 按 `O` 键在**三态**间循环：

| 态 | 看什么 |
|---|---|
| 成品 | 正常审稿 |
| 叠参考图（multiply 半透明） | 分区边界对不对得上 |
| 叠差异图（screen 发光） | 哪里漏排了；成片高热区 = 真正的偏差 |

> 差异图由 `python tools/refgrid.py <ref> --shot <pageNN>` 生成；没跑过就只有两态。
> 参考图与差异图**仅内部比对，不随成品分发**。

改完 box 再跑一次 `python tools/reffit.py` 看骨架吻合分（告警级）：

```
python tools/reffit.py              # 全部页
python tools/reffit.py page05       # 只算一页
python tools/reffit.py --tol 0.02   # 放宽容差
```

分数低时它会**指名缺哪几条缝**（例如「缺这几条横缝：22.6%、62.0%」）——照着改 box
的 `y`/`h`。**这一步要迭代 2–3 轮。** 若提示「证据弱 / N/A」，说明这张参考图本身
是照片主导、投影量不出骨架，此时只能人工看 `_shots/report/<page>_skeleton.png`
的第三联（青 = 参考图边缘，红 = 你的框）。

## 二·附 · 十二维解析台账（★「复刻到什么程度」的全部定义）

`refscan` 的投影只量了**一个**维度（文字排版：带缝 + 分栏）。
「参考图解析」这件事其实是**十二个维度**，少一个维度，成品就会在那一处看起来「没按参考图做」——
而流程不会报任何错。所以每个维度都要**落字**，落到 `_shots/report/refdims.json`。

> **这份台账为什么从八维扩到十二维** —— 一次真实复盘：
> 八维跑起来后，八套判据全部退出码 0，用户仍逐条点出**七处不符**。
> 把七点对上八维，发现其中五点落在**八维根本没覆盖**的地方：
> 背景色（①只量中位亮度）、块内三行结构＋货币写法（②只量带缝分栏）、
> 排列方式（④只统计字色令牌）、卡内排版（⑥只知道「有个白卡」）、
> 主体位置（⑦只登记生图提示词）；另外两点对应的维度**整条不存在**：
> 遮挡关系（第 2 点）、画面密度（第 5 点）。
> **教训：没量的地方不是「没问题」，是「看不到问题」。**

| # | 维度 | 机器能算什么 | 人工必须核什么 | 核对抓手 |
|---|---|---|---|---|
| ① | 颜色 / 色调 | **★四角背景基色**（丢掉被主体/白卡污染的角取中位，给出**有符号冷暖轴 R−B**）+ 中位亮度/饱和/主轴色相/亮部占比 + 六色板 | 偏移是**品牌覆盖**还是**跑偏**；要在台账里写明归属 | `refdims.py --bg` / `--plate` |
| ② | 文字排版 | 参考结构线（横带缝 + 竖分栏）↔ layout 边框**命中率**；**★块内纵向结构**（同 x 带内按 y 串成的字号链，给「首/末字号比」）；**★货币写法** | 未命中的线是「版面分区」还是「参考图照片内部纹理」；参考刊那个块内链是几行、字号比多少 | `refdims.py` + `edgefit.py` |
| ③ | 文字字体 | layout 的 font 角色分布；`fontMap` 条数 == `fonts` 角色数 | **替代体与参考刊同不同族**（相似点 + 差异逐条写） | `fontcheck.js`（真用了内嵌字体）+ `references/05` 六步 |
| ④ | 文字颜色 | 字色**令牌**分布、字号区间、**★对比角色**（亮底暗字 / 含亮色压照片字） | 文字压照片**读不读得出来**；参考刊本页的对比角色与目标比值 | `contrastcheck.py` |
| ⑤ | 标签元素 | 成品侧 badge/torn/bubble/label/logo 清单 | **参考图本页有几个、什么形状、压在什么上** | 人工读图；`refgrid --zoom --crop` 放大取证 |
| ⑥ | 遮盖块 | 成品侧 panel/mask/band（及带 `bg` 文字）清单与面积 | 参考图的白卡/色带/半透明面板位置是否一致 | 同上；`blockcheck.py` |
| ⑦ | 模特动作 **/ 主体位置** | ASSETS.md 的 AI 生成登记；**★主体几何**（成品侧三级来源链：`occlude` 掩膜 → **素材抠像 + box 映射** → 成品页整页抠像兜底，见 §9.2.5）。**★参考侧有污染闸门**：合成页上 rembg 会把白卡/文字并进主体，`ref_mask_reliability()` 判「不可采信」就改读 `_readings.json` 的人工读数（`clean=True` 的干净源放宽到跨度 0.92 —— 见 §9.2.6）。**★适用性闸门**：`classify_page()` 先判 `portrait`/`multi`/`still`，`still` 页标 N/A 不计缺失，机器判不准时由 `_readings.json.pageKind` 人工声明；**素材侧**没有人物时由 `shotKind` 声明 → 进「**素材缺口**」清单（≠ 核对通过，也 ≠ 硬缺失）。**★失败拆因**：`frame_edges()` 判「照片框缩在页内」还是「框已出血、主体没填满」→ `cause = 版面 / 生图层` | **参考图的景别·朝向·视线·手势·主体轴心 x·四边接触率**（用 `--grid` 网格图读，见 §9.2.2），与提示词逐项对照 | `refdims.py --grid` + `_readings.json`；`herorecut.py --fit-touch` 反解重裁；不一致 → **重做生图，不是改文案**（但**先看 `cause`**：`版面` 的别去重生成） |
| ⑧ | 重叠编排 | `subjectguard.py`（实底小模块 vs 主体核心）、`check_faces.py`（vs 五官） | 参考刊允许哪些大模块压人；把允许的写进台账 | `subjectguard.py` + `check_faces.py` |
| ⑨ | **排列方式** | 每个大字号 zone 的 `横排 / 竖排 / 斜排 / 弧排`（读 `writing` / `rotate` / `arc`），弧排另给 `r` 与 `mid` | 参考刊那些大字**各自怎么排**；弧排要估弧度与倾角 | `refdims.py`（⑨ 段）+ 人工读图 |
| ⑩ | **遮挡关系** | 本页声明了几条 `occlude`、每条掩膜挖出的**洞**在哪（= 主体轮廓）；**待问清单**：哪些大字正压在出血人像上 | 参考刊**哪个元素被主体挡住**（刊头？价格？）、挡掉几成、是整字消失还是切一角。参考遮了而成品没声明 → 就是那类漏 | `refdims.py`（⑩ 段） |
| ⑪ | **卡内排版** | 每个 panel 的子元素结构：子元素数、`重复行`（等高等距 ≥2 次）、罫线数、有无角标、有无标题、有无底注；**空卡直接报** | 参考刊卡内结构 = 角标？标题几行？重复行几行（编号+名称+罫线）？有无底注？ | `refdims.py`（⑪ 段） |
| ⑫ | **画面密度** | 参考/成品各 3×3（可 4×4）宫格的**局部梯度能量占比**，逐格对照，报 `dead cell`（参考有内容 + 成品近乎全空 + **该格元素覆盖率 < `--cover`**）、`flat cell`（**素材平坦格**：有影像元素占满但那素材本身低对比 → 告警级不阻断）与 `gap cell` | 该格参考刊装的是什么（照片？文字？），你的空格该由什么来填 | `densitycheck.py --plate` |

```bash
python tools/refdims.py --write --plate --check    # 出台账 + 色板/基色对照图 + 完整性核对
python tools/refdims.py --bg                       # 只看背景基色（第 1 点那种问题一眼可见）
python tools/densitycheck.py --plate               # 逐格密度热力图
```

**纪律**：`--check` 的 `manual` 字段**留空即视为未核对**，不许当成已核对。
`--check` 只把「机器能判的缺失」算硬失败；其余列为**待人工核对清单**，逐页过一遍再落字。
当前硬失败清单：①缺参考/成品图、**①背景基色跑偏（|Δ(R−B)| > 10）**、
②refscan 无读数、**②货币写法出现 `¥/￥`**、③fontMap 不完整、
④压照片的浅色字没有 `shadow`、**⑪panel 是空卡**、**⑫有空档格**、⑦无 AI 生成登记、
**⑦主体构图跑偏（头心 x 差 > 0.06 或触边率差 > 15pp）** —— 逐边报 `cause`，据此决定改版面还是回生图层、
**⑦参考侧掩膜不可采信且人工读数缺失（= 未核对）**、
**`_readings.json` 键名/类型不合法（写了但读不到）**。

> **「素材缺口」是第三态**，既不算硬失败也不算通过：`shotKind`/`pageKind` 判本页第 ⑦ 维
> **没有定义**（素材侧根本没有人物主体）时，它单列成一节打印。
> 硬失败是「量到了、不达标」，素材缺口是「量不了，因为素材里没这个对象」。
> 两者在报告里必须是两句不同的话 —— 混在一起就会把「没量」当成「没问题」。

## 四、zone 规格

```jsonc
{
  "id": "s1-h",                   // 必填。全页唯一。文案槽位选择器就是 "#s1-h > .t"
  "kind": "text",                 // 可选，默认 "text"
  "box": [0.012, 0.850, 0.226, 0.050],   // 必填。见 §四.1
  "parent": "cp",                 // 可选。★子元素：box 以**父框**为坐标系，DOM 也嵌进父元素里。见 §四.3
  "occlude": "images/submask.png",// 可选。★主体遮挡掩膜（CSS mask 语义：低 alpha = 挖空）。见 §四.4
  "arc": { "cx":0.5, "cy":4.4, "r":0.88, "mid":-90 },  // 可选。★弧排文字。见 §二·第5步
  "tpl": "${1}<br>${2}",          // 文字类必填。${n} 是槽位
  "src": "images/step-1.jpg",     // 图片类必填
  "alt": "步骤一 细节",            // 图片类建议填（受禁用词检查）
  "mod": "is-hero",               // 可选，附加 class
  "valign": "middle",             // 可选：top/middle/bottom（框内垂直对齐）
  "overlapOK": true,              // 可选：豁免「文字框互压」检查（确有设计需要时才用）
  "variant": ["rotate", "frame"], // 可选：允许变体引擎扰动本框（见下）
  "style": { /* 见 §四.2 */ }
}
```

**`kind` 与 `style.font` 都是白名单**（`build.js` 校验，写错直接 fail，不再静默画空 div）：

- `kind`：`text` / `image` / `cutout` / `mask` / `rule` / `band` / `panel` /
  `badge` / `torn` / `bubble` / `logo` / `label`
- `style.font`（**连字符版**）：`serif` / `sans` / `script` / `script-fat` / `latin` / `latin-ital`

### 4.3 `parent` —— 卡内排版（★没有它，白卡就只能「2×2 生硬排列」）

参考刊的白卡里从来不只是一堆等大的框：它有**角标气泡、标题、编号色列、每行之间的罫线、底注**，
每一样都有各自的横向起点与宽度。用「画布坐标」去摆这些子元素，改一次卡片位置就要重算全部子坐标。

`parent` 把这件事变成嵌套：**子 zone 的 `box` 以父框为坐标系**，渲染时 DOM 也真正嵌进父元素里
（父元素带 `overflow`/`border-radius` 时子元素会被正确裁切）。

```jsonc
{ "id": "cp", "kind": "panel", "mod": "is-white", "box": [0.712, 0.014, 0.276, 0.524], "style": { "radius": 3 } },
{ "id": "cp-tag", "parent": "cp", "kind": "bubble", "box": [-0.070, -0.011, 0.615, 0.058], "tpl": "${1}" },
{ "id": "cp-r1",  "parent": "cp", "kind": "rule",   "box": [0.048, 0.307, 0.906, 0.0016], "style": { "soft": true } },
```

三条纪律：

1. **坐标是相对的**：`x=-0.070` 是合法的，表示「伸出卡片左边缘 7%」——角标气泡就是这么挂的。
2. **判据要读折算后的坐标**：`layout/NN.json` 里存的是相对坐标，
   凡是「谁和谁互压」这类跨块判据，必须读编译期折算过的 `layout/_resolved.json`
   （判据统一走 `tools/_lay.py`）。**直读原文会算出假互压。**
3. **卡片内容要成结构，不要等大平铺**。一个像样的信息卡至少要有：
   ① 角标（`bubble`/`badge`/`torn`）；② 标题（字号 ≥ 14，可 1–2 行）；
   ③ **重复行**：同 kind、等高、**等距** ≥ 2 组（编号 + 名称 + 罫线）；
   ④ 说明段；⑤ 底注（字号 ≤ 10）。
   `refdims.py ⑪` 会把这几项逐个量出来，**panel 没有 `parent` 子元素直接算硬失败（空卡）**。

### 4.4 `occlude` —— 主体遮挡（★「刊头被模特头部挡住」的唯一正确做法）

参考刊的大字艺术刊头被模特的头/发遮掉一部分，这在版面上是**层级关系**，不是「把字裁掉」，
也不是「把字挪开」。做法：给那个 zone 声明一张**主体轮廓掩膜**（RGBA PNG），
引擎把它作为 CSS `mask-image` 打在**这一层**上。

```jsonc
{ "id": "mast-brand", "kind": "text", "box": [0.014, 0.032, 0.620, 0.142], "tpl": "${1}",
  "occlude": "images/p01-submask.png",
  "style": { "font": "serif", "size": 186, "weight": 900, "color": "pink", "z": 10 } }
```

四个坑，全踩过：

1. **CSS mask 的语义是「alpha 低 = 挖空」**，不是「alpha 高 = 主体」。
   量产掩膜时（`herorecut.py --emit-mask`）吐的是 CSS mask 语义，低 alpha 处才是洞。
   把极性读反，算出来的头部轴心会差一倍（实测 0.559 vs 真值 0.335）却看不出错。
2. **`file://` 协议下外链 PNG 掩膜会被同源策略静默拒绝 —— 元素整块消失，且不报任何错。**
   引擎必须把它**内联成 data URI**（`build.js` 的 `maskDataURI()` 已做，并加体积闸与通道检查）。
   排查现场若出现「加了 occlude 元素就没了」，第一件事就是查这条。
3. **必须是带 alpha 通道的 PNG（color type 4 或 6）**。灰度 8bit（type 0）没有 alpha，
   拿来当 mask **不生效且不报错**。引擎会对非 4/6 的掩膜发警告。
4. **掩膜尺寸必须等于画布尺寸**，否则遮挡整体错位（引擎有硬断言）。
   用 `herorecut.py --size <画布WxH> --emit-mask` 出，就天然对齐。

**怎么产这张掩膜**：`python tools/herorecut.py <出血照> <out.jpg> --dx F --bg "#RRGGBB" --size WxH --emit-mask out-mask.png`
—— 它取主体掩膜（rembg u2net，本地已缓存）→ 平移 → 重铺背景 → alpha 合成，
**同一次运算吐对齐的遮挡掩膜**。背景基色用 `--bg-from <参考图>` 直接从参考图三角量。

### `variant` —— 允许变体引擎扰动

默认**不动**任何框（`node build.js` 保真）。要「一物一版」时用 `--seed <SKU名>`，
此时只有**显式声明**了 `variant` 的框会被扰动：

| 值 | 效果 |
|---|---|
| `rotate` | 微旋转 ±1.5°（保留原有角度，只加扰动） |
| `frame` | 相纸厚度三档（normal / thin / wide） |
| `framing` | 重取景（只动没指定 `object-position` 的图） |
| `reorder` | 子元素整体倒序（配对的图文一起搬） |

另有**页面级**三条轴（由 seed 决定，不需要声明）：页边母题、照片调色、标题字距。
调色**只作用于 `image`**，`cutout`（抠图产品）与 `logo` 一律不滤镜——否则颜色与实物不符。

### 4.1 `box` —— 归一化坐标（★核心约定）

**数组形式 `[x, y, w, h]`，全部是 0–1 的小数**，相对本页 `canvas`：

```jsonc
"box": [0.012, 0.655, 0.226, 0.178]
//      x=1.2%  y=65.5%  w=22.6%  h=17.8%
```

**为什么用比例而不是 px**：换画布尺寸（同一份骨架套到另一张尺寸的参考图上）不用改一行。
引擎在渲染时乘回 px；`copycheck` 的静态互压检查也用同一套换算，所以检查结果与渲染结果一致。

对象形式 `{ "x": 24, "y": 1145, "w": 309, "h": 311 }` 也支持（绝对 px），
但**只在确实需要像素精确时用**——它会绑死画布尺寸。

### 4.2 `style` 字段

| 字段 | 适用 kind | 值 | 说明 |
|---|---|---|---|
| `font` | 文字类 | 角色名 | `serif`/`sans`/`script`/`script-fat`/`latin`/`latin-ital` → `var(--font-*)` |
| `size` | 文字类 | number(px) | 字号 |
| `weight` | 文字类 | number | 字重。**超过品牌 `maxWeight` 要下调**（见 `references/02`） |
| `tracking` | 文字类 | number(em) | 字距 |
| `leading` | 文字类 | number | 行高倍数 |
| `indent` | 文字类 | number(px) | 首行缩进 |
| `color` | 文字类 | 令牌名 或 `#hex` | 令牌名跟着品牌包走 |
| `align` | 文字类 | `left`/`center`/`right` | 水平对齐 |
| `writing` | 文字类 | `"v"` | 竖排 |
| `upright` | 竖排时 | `true` | 竖排里的拉丁/数字正立（不旋转） |
| `style` | 文字类 | `italic` | 斜体 |
| `shadow` | 文字类 | CSS text-shadow | 压照片的白字必备（否则看不清） |
| `bg` | 全部 | 令牌名 / `#hex` / `none` | 底色 |
| `z` | 全部 | number | 层级。**标题类给 10+，照片 1–5，页脚 30** |
| `rotate` | 全部 | number(deg) | 旋转 |

**令牌名白名单**：`paper` / `paper-warm` / `paper-cream` / `paper-grey` / `ink` / `ink-2` /

## 六、常见骨架族（原型库）

解析新参考图时，先判断它属于哪一族，然后从对应原型起手改。

| 族 | 特征 | 关键 zone | 难点 |
|---|---|---|---|
| **A 出血人像页** | 一张大图占半页以上，字号大 | `hero(bleed)` + 编号 + 4 格 | 编号压图的可读性（要 shadow + 描边） |
| **B NEWS 双栏页** | 上下两块，每块左右分栏 | `news01/02` 的 kicker/h/p | 两栏字数不等时长栏把短栏挤歪 |
| **C Step 四格页** | 4 或 3 等分，图 + 小标 + 说明 | `sN-img/-no/-h/-p` | 说明文溢出（中文比日文长 15–20%） |
| **D 满版深色页** | 深底 + 白字巨型直排 | `panel` + `v` 文字 | 深底下细字不可读 |
| **E 产品盘页** | 一件产品多个角度／多个色 | `cutout` 多个 + 字母标注 | 抠底透明边界（必须跑 `alphabox.py`） |
| **F 拱形 HOW TO 页** | 拱形裁切 + 步骤 | `mask(arch)` + 编号 | 拱形内的文字要避让弧线 |
| **G 规格栏页** | 表格化规格 + 细节特写 | `rule` + `label` | 罫线与文字的对齐 |
| **H 双人/双物页** | 左右对称两个主体 | 两个 `hero` + 中间 `rule` | 中缝的留白 |

> 这八族是从实际参考图里归纳的，不是穷举。**遇到不属于任何一族的新骨架，就按 §二 的八步解析**（第 0 步先跑 refscan）。

## 七、自检清单（写 JSON 时随时对）

- [ ] 先跑过 `python tools/refscan.py`，带缝与分栏**照它的读数写**，不是眼睛估的
- [ ] 每页 `canvas` 写的是**自己参考图的真实尺寸**（不要一律抄 1366×1748）

## 八、反复踩过的坑

1. **竖排框高不足。** `writing: "v"` 时内容会按字高竖向排，框高不够就溢出。
   竖排 box 的 `h` 要给到「字数 × 字号 × 行距」的估算值再留 15% 余量。
2. **`.t` 不继承框高导致溢出判定不准。**
   引擎已在 `css/layout.css` 里用 `.z--text > .t { height: 100%; }` 修好
   （带 `valign` 的框用 `height: auto`）。**不要把它改回去**——改回去 `copycheck` 就测不准溢出。
3. **`parent` 子元素的相对坐标会被判据当成画布坐标。** 白卡里的 `pageno ∩ cp-foot 3047px²`
   就是这么来的假互压。解法是编译期落一份折算过的 `layout/_resolved.json`，
   判据统一读它（`tools/_lay.py`）。
4. **容器框 ≠ 字的墨迹。** 判「文字互压」时拿 `box` 比，会同时产生假阳性（框碰了、字没碰）
   与假阴性（字碰了、框没碰）。普通文字要量渲染后 `Range.getBoundingClientRect()`；
   **弧排/旋转大字的框是松包围盒**，必须沿路径采样出**带形**再比
   （同一个弧排字，用容器框报 24640px²，用带形报 0 —— 差的就是「把空白也算成字」）。
5. **`occlude` 的掩膜在 `file://` 下外链会静默失效**（见 §四.4）。
6. **样式表里写死色值会绕过品牌约束。** 压照片的加深档要按对比度反算（见 §九），
   但**取值仍然写进品牌包 `palette` 的令牌**，版式只引用令牌名。

## 九、三个「不能用眼睛判」的量

### 9.1 压照片的字色：按对比度反算，不要凭感觉调深

「字压在人像上读不读得出来」是**可以算的**，不要靠调色相试。
流程：`contrastcheck.py` 量出该框内的**背景中位灰度**（文字实际落座的那层底）→
按 WCAG 反算需要的字色亮度 → 写进品牌包令牌。

反算公式（相对亮度 $L$，正文需比值 ≥ 4.5，≥18px 大字 ≥ 3.0）：

$$L_{ink} \le \frac{L_{bg} + 0.05}{4.5} - 0.05$$

实例（本项目实测）：`fam` 那行底下是灰度 159（人物肌肤/薄纱），
$L_{bg} = 0.347$ → 需要 $L_{ink} \le 0.038$。原来的 `#7A4A55` 是 $L=0.097$（比值 2.70，不够），
压到 `#4B2731` 得 $4.85$。**颜色不是审美调整，是算出来的**；换底就要重算。

两条配套纪律：

- **声明了 `occlude` 的块跳过本判据**（`contrastcheck` 会标 SKIP 并列出来，不静默跳过）。
  它的框被主体有意盖住一大半，框内中位色是「头发/皮肤」而不是字的底，
  算出来的比值（实测 1.03）量的是「字 vs 遮挡物」—— 而遮挡物的意义恰恰是**不该**看见。
- **浅色字（`paper*` 令牌）压在照片上必须给 `shadow`**，`refdims ④` 会硬拦。

### 9.2 主体位置与留白：是**生图层**的事，不是排版层

参考刊的封面主体常常顶到三四条边（裙摆满幅），所以画面「满」。
如果主体只触下边、右边接触率 0，右侧就是一片平底 —— **画面会显得空**。

这件事的能量：页面上若有 `occlude` 掩膜，`refdims ⑦` 直接从掩膜的**洞**里量出
主体 bbox、头部轴心 x、**四边接触率 L/R/T/B**（口径：该边 3% 宽带内主体像素占比）。

#### 9.2.1 ★参考侧不能自动量 —— 合成封面会把版面元素并进「主体」

参考图是**合成页**（模特 + 白卡 + 刊头 + 提示条）。直接对它跑 `rembg`，结果是：
**人和右上白卡连成同一个连通域**。实测一份参考封面：

| 量法 | 结果 | 问题 |
|---|---|---|
| `rembg` 跑参考图 | 上半幅跨度 **0.203–0.968（0.77）**，头心 x **0.581** | 人与白卡连片，列投影**没有缺口**可切；真值约 0.38，差 0.2 且不报错 |
| 暗块法（`dark_blob`） | 头心 x **0.551** | 混进刊头大字、卡内黑字、红色提示条 |
| 非背景法（离四角底色 > tol） | 头心 x **0.497** | 刊头 S、顶部提示条、白卡全是「非背景」 |

三条路都不通。所以 `refdims.py` 加了**污染闸门** `ref_mask_reliability()`：

```
上半幅跨度 > 0.60    （人不可能横跨 0.60 以上）
或 上半幅覆盖率 > 60% （上半幅几乎填满 → 一定混进了版面块）
→ 判定「不可采信」，该页 ⑦ 改用网格人工读数
```

闸门触发不是报错，是**换通道**：参考侧改读 `assets/ref/_readings.json` 的人工读数，
成品侧继续用掩膜（照片是干净的，读数可信）。

#### 9.2.2 人工读数怎么读、写在哪、写错会怎样

读图工具（打格子，把「凭感觉」变成「数格子」）：

```bash
python tools/refdims.py page01 --grid
# → _shots/report/page01_refgrid.png
#   左参考 / 右成品 并排，20×20 网格，x 刻度每 2 格标注，
#   四边 3% 带涂半透明蓝（那正是「四边接触率」量取的那一条），y=0.35 头带下界画绿线
```

读数写在 **`assets/ref/_readings.json`**（不是 `_shots/report/refdims.json` ——
后者是 `--write` 的产物，每次覆盖，人工读数写在那里会被抹掉）：

```jsonc
{ "page01": { "pose": {
    "头心x": 0.35,
    "触边率": { "L": 48, "R": 40, "T": 33, "B": 100 },
    "依据": "网格图：两眼中心落在 x 0.30–0.40 带内；头发顶边 y=0 处横跨 0.245–0.575；礼服铺满画幅底",
    "读图工具": "_shots/report/page01_refgrid.png"
} } }
```

**键名有 schema 校验**（`READING_SCHEMA`）。为什么要：把 `头心x` 写成 `头心X`、
把 `触边率` 写成 `触边`，判据会**静默读不到** → 又退回「未核对」，而画面上一切正常、零报错。
`--check` 现在会当场点名：未知键 / 类型不符 / 缺「需」键 三类都算失败。

#### 9.2.3 ★★触边率**单独做目标函数会被作弊**

把「四条边接触率对齐参考刊」当唯一目标去搜 scale/dx/dy，会解出 `scale=1.655`：
四条边全部达标 —— **但画面上头已经没了**（主体顶边跑到 −0.615，整张脸裁在画幅之上）。

> **接触率高 ≠ 构图对。** 判据本身可被 gaming，这是判据设计的问题，不是执行的问题。

所以 `herorecut --fit-touch` 的约束与目标**分离**：

| | 内容 | 违规处理 |
|---|---|---|
| **硬约束 A** | 头部完整性：主体顶边不得高于 `-top_cut`（默认 5%）；头部带（y<0.35）覆盖不得低于重排前的 `head_keep`（0.55）倍 | **丢弃该解**，不参与打分 |
| **硬约束 B** | 头心 x 必须落在参考值 ± 0.06 | 同上 |
| **目标** | 未达标边的接触率平方误差和 | 只在这些约束内优化 |

另三条纪律（都是实测踩出来的）：

1. **已经达标的边退出目标函数**。否则为了把 R 从 0 拉到 40，L 会被从 41.9 压到 24 —— 修一条坏一条。
   ⚠️ 但「冻结」只把它移出目标，**并不保证它不退化**（放大主体本身会把内容推出画幅），
   所以工具必须**如实打印四条边 before→after**，让取舍显形。
2. **粗搜 + 局部精修，且两阶段用同一分辨率**。曾用 1/4 分辨率粗搜、全分辨率精修：
   粗搜那一层把 `--shrink 2px` 按**全分辨率像素**算，在 1/4 图上等于 8px，
   把掩膜侵蚀到「头部覆盖不足」→ 约束全部失败 → 报「无解」。**这是自己给自己设的假门槛。**
3. **评分必须带上 `--shrink` 的腐蚀**。`main()` 在评分之后还会 erode 一次；
   不预先把这步算进去，会挑出「纸面上 28.8%、落地 23.9%」的解。
4. **缩放支点必须与搜索支点一致**。搜索按**头顶**缩放、应用按 **bbox 底边**缩放，
   会得到「预测 R 41%/T 35%，落地 R 0%/T 2%」—— 解出的参数与落地的画面根本不是同一张。

#### 9.2.4 搜不出解时，正确的结论是「回生图层」

```bash
python tools/herorecut.py images/p01-hero2.jpg --size 1280x1617 --check \
    --head-x 0.35 --fit-touch "T=33,B=100,R=40"
```

工具会在**约束穷举后**如实报残余，并给出归属判断：

```
（搜索中丢弃 1136 组越约束的解：头部完整性 / 头心 x）
★★结论：**这不是参数问题**。这张照片里没有能填满 R 的内容
   （参考刊靠裙摆铺满，本片是棚拍平底裁切）。
   要解决只能回生图层：重出（提示词写清 背景基色 / 主体轴心 / 主体触边 三件事）
   或换一张主体更满的画幅。**不许用拉长卡片、加装饰去填** —— 那是掩盖。
```

> ⚠️ **不触边不能用排版去修。** 拉长卡片、加装饰块、把字号放大去填那些格 —— 全是掩盖：
> 参考刊那一格是被**照片**填满的，你填进去的是版式元素，形状与层次都不对，
> 而且一改产品素材就全部失效。
> **正确做法是回生图层：重出或重裁照片。**
> 这条与 §二·附 的 ⑦ 是同一条规矩：**主体不对 → 重做生图，不是改文案、也不是改版式。**

#### 9.2.5 ★★页类型闸门 —— **不是每一页都有「头心 x」**

参考图是**混编**的。本项目这 9 张：`p01` 人像封面（人 + 右上白卡）、
`p02` **静物拼贴**（包、鞋，没有主体模特）、`p09` **三格美人图**（并排三个头）。
而第 ⑦ 维的量法（头部带 = 上 35%、头心 x、四边接触率）**只对「单一主体」的页成立**。

不判类型就把口径套上去的后果：

- 逼一页**没有主体的静物图**去填「头心 x」→ 那不是核对，是**逼人编读数**；
- 用户只有两条路：编个数糊过去，或被一条**永远清不掉的硬缺失**卡住。

所以第 ⑦ 维前面加一道**适用性闸门**（`classify_page()` → `subj_verdict(applicable=False)`）：

| 页类型 | 判定 | 第 ⑦ 维怎么办 |
|---|---|---|
| `portrait` | 一个大主体 | 正常判据：头心 x ±0.06 + 四边接触率 ±15pp |
| `multi` | **≥2 块互不相连**的主体（用**连通域**判，不是列投影） | **头心 x 无定义** → 只对表四边接触率 |
| `still` | 抠像没分出前景（占比 < 1.5%） | **不适用** → 标 N/A，**不计硬缺失** |

> ⚠️ **为什么多主体要用连通域而不是列投影**：三格/双栏的照片常常**首尾无缝** ——
> 本项目 `page09` 的三格 box 是 `0.045+0.314=0.359=下一格起点`，正好相接。
> 列投影会连成一整段 → 把 `multi` 误判成 `portrait` → 再被「跨度 > 0.6」的闸门拦掉，
> 一组本来正确的读数就白丢了。

**机器判不准时，由人声明。** 合成页上 rembg 不可信（实测 `p02` 静物拼贴被判成跨度 0.95 的一整块），
所以 `_readings.json` 允许写：

```json
"page02": { "pageKind": { "kind": "still", "依据": "读图：本页是包/鞋拼贴，没有主体模特" } }
```

声明之后 `effective_schema()` 会把该页 `pose` 的必填键降级为空 ——
**不再要求一个不存在的量**，也不再计入「留空未核对」。

> ⚠️ **三处词汇表必须一致**：`PAGE_KINDS` / `classify_page()` / `NA_KINDS`。
> 早期版本 `classify_page` 返回 `single`/`none`，而 `PAGE_KINDS` 用 `portrait`/`still` ——
> 人工声明 `still` 之后判据**读不到**，照旧报「未核对」。
> 又一次「写了但读不到」的静默失败：**加一个词表，就得同时检查所有消费方。**

**成品侧的来源链**（三级，按可靠性降序）：

| 优先级 | 来源 | 可靠性 | 说明 |
|---|---|---|---|
| 1 | `occlude` 掩膜 | 高 | 产出时 `herorecut --emit-mask` 生成，与素材同源。**只有「刊头被遮」的页才有** |
| 2 | **素材抠像 + box 映射** | 高 | 对 `layout` 里 `kind:"image"` 的素材抠像，按 `object-fit: cover` **精确**映射回画布。**每页都有** |
| 3 | 成品页整页抠像 | **低（仅兜底）** | 显著性检测在整页图文上常漏主体：实测 `page05` 洞 0.6%（整块漏人）、`page08` 洞 4%（只抠到一角**却照样驱动判据**）→ 设 `SHOT_PAGE_MIN = 8%` 下限 |

> ⚠️ **第 ⑦ 维曾经绑死在 `occlude` 上** —— 而 `occlude` 只有「刊头被遮」一个场景需要，
> 于是静物页、无遮挡人像页**永远**拿不到成品侧读数，判据只能永久报「未核对」。
> 实测 `p05` 参考侧已量出**可信**读数（触边 L0 R0 T0 B3，跨度 0.28），成品侧却因为
> 「本页无 occlude」卡死 —— **判据把自己锁死了**。（主体位置 ≠ 版面原语，必须解耦。）

> ⚠️ **`pages()` 不含 `src`**（`_lay` 精简过，只留给坐标类判据）。
> 素材通道早期直接吃 `pages()` 的结果 → 永远找不到 image zone → **整条通道一条都没生效**，
> 而输出上只看到「无读数」，不报错。取 `src` 必须回读**原始** `layout/NN.json`，
> `box` 仍用折算后的（按 zone id 对上）。

> ⚠️ **多主体页的闸门只该对「干净的抠像」放宽**（`clean=True`：素材抠像 / `occlude` 掩膜）。
> 参考图与成品页是**合成页**，跨度大很可能真混进了版面块 ——
> 实测 `page09` 参考图 rembg 给出触边 **L88 R61 B100**，那是「三格 + 文字」糊成一片的产物，
> 拿它去对表会得出「成品侧三条边全不达标」的**假结论**。

#### 9.2.6 ★★「不触边」的两个原因必须分开 —— 判据给错诊比没有判据更坏

⑦ 的结论过去只有一句：**「→ 生图层」**。但「主体没触到页边」有**两个完全不同**的原因：

| 原因 | 现象 | 正确修法 |
|---|---|---|
| **版面层** | 照片框本身就缩在页内（照片是`object-fit:cover` 填满框的，主体触到了**框**的边，但框没到**页**的边） | 把框拉到出血。**重生成照片纯属白干** |
| **生图层** | 框已满版到页边，是照片里主体没填满画幅 | 回生图层重出 / 用 `herorecut --fit-touch` 重裁 |

实测本项目 `page09`（三格并排写真）：照片行 `x 0.045–0.962` **内缩 4.5%**，
判据报「→ 生图层」—— 照那句话去做会去**重新生成三张照片**，
而真正的修法是把 `p1-img` 的 x0 拉到 `0`、`p3-img` 的右缘收到 `1`。

> **一条给错诊的判据比没有判据更坏**：它花掉的时间比省下的多，而且看起来是「在按流程办事」。

实现：`frame_edges(pid)` 量出本页**照片区**（`kind ∈ image/cutout/mask`）四边距页边多少，
逐边给 `cause`：**框距页边 > 1% → `版面`；否则 → `生图层`**。
硬缺失文案按 `cause` 给出对应修法，打印时附上「照片框距该页边 X%」。

同理，⑦ 的 `layer` 字段也是**版面优先**：同一页里只要有一条边是「版面」成因，
就先把版面修完再谈重出 —— 因为拉框本身会改变主体的框内裁切。

**顺带一条：`clean=True` 的干净源，跨度上限必须放宽。**
`ref_mask_reliability()` 的 `span_max=0.60` 是针对**参考合成页**标的；
而素材侧的 `clean=True` 源是**单张照片**，里面根本不存在「版面元素」，宽跨度只可能是构图本身。
实测「本项目 `p04-hero.jpg` 上半幅跨度 0.678、`p06-photo.jpg` 0.706」——两者都是近景人像，不是污染，
却被 0.60 拦下 → 这两页的成品侧**永远拿不到读数** → ⑦ 对它们只能常年「未核对」。
故 `clean=True` 时放宽到 `span_max=0.92 / cover_max=0.85`；参考合成页与整页抠像**保持严格**。

**再一条：两边量法不同造出来的差异，必须先统一量法，再谈达标与否。**
参考侧 rembg 跑**整页**只挑显著主体（实测 `p03` 掩膜 bbox `x 0.38–0.718`，右侧三张缩略图被当作版面元素排除）；
而成品侧若不筛选，会把**主写真 + 三张缩略图**并成一块 → 上半幅重心被缩略图拉到 0.643（参考 0.567），
差 +0.076 被判「跑偏」。**分不出这 0.076 里有多少是真的** —— 这种差异会让人去改一个其实没问题的地方。
处置：成品侧只取「**面积最大的一组影像**」（面积 ≥ 最大 × 0.35），缩略图 / 色见本小图不进主体通道。



`densitycheck.py` 报三类：`dead_cell`（参考有内容、我方近乎全空**且该格连元素都没放**）、
`flat_cell`（**素材平坦格**）与 `gap_cell`（只是偏空）。

- **`dead cell` 是硬失败** —— 那格我方什么都没有，一定是漏了元素。
- **`gap cell` 只是预警，不要拿它去堆内容**。实例：本项目 page01 的右上卡格
  参考 37.2 / 成品 9.5，看着差很多 —— 但参考卡是**卡通周边 9 件套**（高纹理），
  我方是**一件内衣 4 色**（纯净商品图）。内容不同 → 密度天然不同。
  **为一格指标去塞图案，就是把判据当成目标去迎合**（Goodhart 定律），
  而且违反品牌「静かな余白」的基调。正确处置：把该格写进台账，
  注明「内容差异，非缺失」，人工签字放行。
- **`flat cell`（素材平坦格）告警级，不阻断，而且禁止用加图案的方式消掉它。**

> ⚠️ **单一指标一定会有假阳性，而假阳性会把人推向错误的修法。**
> 「局部梯度能量」衡量的不是亮度而是「这里有没有边缘/纹理」——
> 本项目商品素材是**淡彩商品图**（浅绿/浅紫文胸压浅灰底），梯度天然只有 0.9–2%；
> 而参考刊那一格是「深色包袋 / 模特蕾丝裙」20–40%。
> 于是 `densitycheck` 把一个**被商品图完整占满**的格报成「空档格」，
> 还给出「补一个该格该有的元素」的建议 —— **那条建议正是 Goodhart**：
> 往里塞图案，账面变绿，画面变脏。
>
> 修法不是换阈值（换阈值只是把假阳性挪个位置），而是**引入第二条证据**：
> `zone_coverage()` 逐格算「被 `image/cutout/mask/logo` 盖住多少」。
>
> | 该格影像元素覆盖率 | 判什么 | 级别 |
> |---|---|---|
> | ≥ `--cover`（默认 **10%**） | **素材平坦格** —— 低对比来自素材本身，不是排版漏了东西 | 告警，不阻断 |
> | < `--cover` | **空档格** —— 参考刊这里塞了东西，你连元素都没放 | **阻断** |
>
> 门槛 10 是**实测标定**出来的，不是拍的：< 1/3 的格（实测 `page03 [2,0]` 0%、`page05 [1,2]` 0%、
> `page06 [1,2]` 25%）人工复核确认确实是空地；≥ 1/3 的格（`page06 [0,1]` 43%、
> `page08 [0,2]` 33%、`page08 [2,2]` 42%）实测都是**被商品图占满、只是淡彩**。
> 门槛再高（55%）会把后者判成空档格 → 假警报；再低（25%）会放过「3/4 是空白纸」的格 → 漏报。
>
> ⚠️ **⑫ 的两条入口必须同源。** `densitycheck.py` 与 `refdims.density()`（⑫ 维）共用
> `_dens.compare` + `_dens.zone_coverage`。曾出现 `densitycheck` 报「OK 无空档格」
> 而 `refdims --check` 仍报 ⑫ 空档格（因为后者没接 `cover` 这一路）——
> **同一维度两套口径，看到两份报告的人无法判断该信谁。**
>
> ⚠️ **平坦格要独立记，不能写成 `elif` / `and not dead_cells`**：一页只要有一个真死格，
> 它其余的平坦格就全从报告里消失 —— 报告看着干净，其实那一页的平坦格一个都没列。
