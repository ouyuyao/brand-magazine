# 05 · 字体识别与替代映射（「尽量保留原刊文字样式」的落地）

> 这条要求的原文是：**「尽量保留原刊的文字样式，如果没有就找最相似的。」**
> 但过去只给了一句口号 —— `fontMap.from`（原刊字体）没有任何判定方法，全靠凭空填。
> 这份文档把它变成**六个动作**，每个动作都有工具、有产出、有可验的凭据。

---

## 一、为什么不能「照抄原刊字体」

原刊标题用的多半是**商用版权字体**（日本杂志常用 リュウミン / 筑紫明朝 / ヒラギノ 等）。
直接照抄有两个问题：

1. **版权**：随项目分发即侵权。
2. **不可得**：本机没有，也无法随包带走。

所以引擎的做法是：**版式只写「角色」，不写字体名**；由品牌包把角色映射到可用字体。
「气质跟原刊、颜色跟品牌」因此是同一套字段的两种取值，不必二选一。

---

## 二、内嵌字体清单（这是你能选的池子）

来源：`css/fonts.css`。**全部 OFL 授权，可随项目分发。**
族名是「引擎中立名」（`Mag *`），不绑定任何品牌 —— 换品牌不必改 `fonts.css`，只改品牌包的 `fonts` 段。

| 角色名（写进 layout 的 `font` 字段） | 内嵌族 | 实际字体 | 气质 |
|---|---|---|---|
| `serif` | `Mag Mincho JP` / `Mag Mincho SC` | Noto Serif JP / SC | 高对比**明朝体**，横细竖粗、笔画末端有顿挫 |
| `sans` | `Mag Gothic JP` | Noto Sans JP | 笔画粗细均匀的**黑体**（角ゴシック），无衬线 |
| `script` | `Mag Script Silk` | Pinyon Script | 极细 copperplate，笔画如丝线（签名式大字） |
| `script-fat` | `Mag Script Ribbon` | Great Vibes | 笔画丰满、转折圆润的手写（浅底上仍清晰） |
| `latin` | `Mag Editorial` | Playfair Display | 高对比 Didot 系拉丁衬线（大写字标 / 数字） |
| `latin-ital` | `Mag Editorial Italic` | Cormorant Garamond Italic | 高对比拉丁斜体（Step / How to 这类装饰词） |

> 中文稿字形：`html lang` 切成 `zh*` 时，`serif` 自动走 `Mag Mincho SC`（`css/typography.css` 负责）。
> 两套都保留 JP 作回落，避免缺字变豆腐。

## 三、识别流程（六步）

### 第 1 步 · 看衬线，定大族

放大参考图里的一个文字块，只问一件事：**笔画末端有没有「脚」**。

| 你看到的 | 判定 | 写进 `style.font` |
|---|---|---|
| 横细竖粗、末端有顿挫 / 鱗；整体有「笔锋」 | 明朝 / 宋 | `serif` |
| 粗细均匀、末端平直、无饰 | 黑体（ゴシック） | `sans` |
| 圆润连笔、有起收笔，仅拉丁 | 手写体 | 细 → `script`；粗 → `script-fat` |
| 只有拉丁、细横线 + 粗竖线对比极强 | Didot 系衬线 | 正体 → `latin`；斜体 → `latin-ital` |

### 第 2 步 · 看排向与字距，补判「是排法不是字体」

- **竖排句**（`writing:"v"`）不改变字体族，只改变排法 —— 别把竖排误判成另一种字体。
- **大写字标字距很宽**（`tracking` 0.15em 以上）→ 多半是 `latin`。
- **正文行距很大、字距松**→ 大概率 `serif`（明朝体排得开）。

### 第 3 步 · 放大取证（这一步要留证据）

```bash
python tools/refgrid.py p05.jpg --zoom 5 --crop 0.60,0.02,0.36,0.16
```

- `--crop x,y,w,h` 用**归一化坐标**（0–1），框住那个文字块；
- `--zoom 5` 放大 5 倍，图上会叠 **每 1% 一条的页面百分比尺**，方便回报坐标；
- 产物 `assets/ref/_grid/<name>_zoom.png`。

配合 `python tools/refscan.py --ref p05.jpg` 确认这个文字块在页面里的占比与位置。

> **证据留档**：把「哪个字块、放大几倍、看到什么特征」写进 `layout/NN.json` 顶部 `"_"` 注释字段。

### 第 4 步 · 选最相似的内嵌字体

对照第二节那张表选。三条常见取舍：

| 原刊 | 选谁 | 为什么 |
|---|---|---|
| 商用日文明朝（リュウミン / 筑紫明朝） | `serif`（Mag Mincho JP） | 同为高对比明朝，字面宽度接近 |
| 角ゴシック（ヒラギノ角ゴ / ゴシックMB101） | `sans`（Mag Gothic JP） | 同为均匀笔画黑体；差异是原刊端点略方，Noto 更圆润 |
| 浅底上的装饰手写 | `script-fat`（不是 `script`） | 细线体（Silk）在浅底上会看不清 |

### 第 5 步 · 写 `fontMap`（**`why` 必须同时写相似点与差异**）

写进 `brand/brand-pack.json` 的 `fontMap` 数组，字段 `role` / `from` / `to` / `why`：

```json
{
  "role": "serif",
  "from": "参考刊标题明朝体（リュウミン系，商用版权）",
  "to": "Mag Mincho JP / SC（Noto Serif JP/SC）",
  "why": "相似点：同为高对比明朝体，横细竖粗的比例与字面宽度接近；差异：原刊汉字骨架更紧、顿挫更锐，Noto 的字面略宽、笔画更平缓。OFL 可商用，规避字体版权。"
}
```

**六个角色每个都要有登记**（`serif` / `sans` / `script` / `script-fat` / `latin` / `latin-ital`）。
只写「相似点」不写「差异」= 不合格：差异那条才是后面出问题时能复查的线索。

写完抄进项目根 `ASSETS.md` 的「五、字体替代映射」表（模板见 `references/04-asset-ledger.md`）。

> `fontMap` 只是**台账**，`build.js` 不读它。真正生效的是品牌包的 `fonts` 段。

### 第 6 步 · 验证（两个工具，各证一件事）

```bash
node tools/fontcheck.js     # 证明：这些节点画的确实是内嵌字体，不是 SimSun 回落
node tools/inkprobe.js      # 证明：字重真的生效（墨迹随权重变粗）
```

两者缺一不可 —— `fontcheck` 只看「用了哪个字体文件」，它看不见「700 到底有没有变粗」。
这也是品牌包 `visual.maxWeight`（常见 500）与出厂版式里 700/900 冲突时，唯一能拿来做决定的依据。

## 四、什么时候可以「就这样」不换字体

- 品牌包 `fonts` 段为空 → 用 `css/tokens.css` 的出厂默认（已内嵌上面六个族），**能跑，可发**。
- 只有当你要用**池子里没有**的字体时，才需要：
  1. 把 woff2 放进 `fonts/`；
  2. 在 `css/fonts.css` 加 `@font-face`；
  3. 在品牌包 `fonts` 段把对应角色指过去；
  4. 在 `fontMap` 登记一条。

> 引擎的**版式层一行都不用改** —— 这就是「角色 vs 字体」解耦的意义。

## 五、常见误判

| 现象 | 真相 |
|---|---|
| 「`font-weight:900` 写了但看着没变粗」 | 多半是**没内嵌对应字重的文件**。跑 `inkprobe.js` 看墨迹有没有变；没变就是没生效，不是错觉 |
| 「字体名读出来是 ExtraLight / Thin，肯定是 bug」 | Noto 的 CJK 分片内部命名与字重无关，实测 400/700/900 墨迹是递增的。**别按名字去"修"** |
| 「竖排句看着像另一种字体」 | 竖排（`writing:"v"`）只改排法不改字体；先排除排法再判族 |
| 「某个字变豆腐块」 | 该字形不在内嵌子集里 → 用系统回落。`html lang` 决定走 JP 还是 SC 字形 |
